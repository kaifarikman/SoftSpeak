## Что такое Backend?

**Backend** (бэкенд) - это "задняя часть" веб-приложения, которая работает на сервере и не видна пользователю. Представьте ресторан: **Frontend** - это зал, где сидят посетители (пользователи видят интерфейс), а **Backend** - это кухня, где готовят блюда (сервер обрабатывает запросы).

### Что делает Backend в нашем проекте?

1. **Хранит данные** - все пользователи, сообщения, чаты хранятся в базе данных
2. **Обрабатывает запросы** - когда пользователь регистрируется, отправляет сообщение или ищет собеседника, Backend обрабатывает эти действия
3. **Проверяет безопасность** - проверяет пароли, токены доступа, права пользователей
4. **Отправляет email** - отправляет коды подтверждения на почту
5. **Ищет совпадения** - находит пользователей с похожими психологическими профилями
6. **Обеспечивает real-time коммуникацию** - через WebSocket отправляет сообщения в реальном времени

### Простой пример работы Backend

**Сценарий:** Пользователь хочет зарегистрироваться

1. **Frontend** отправляет запрос: "Создай аккаунт с email `user@mail.ru` и паролем `12345678`"
2. **Backend** получает запрос и проверяет:
   - Правильный ли формат email?
   - Достаточно ли длинный пароль?
   - Не занят ли этот email?
3. **Backend** сохраняет данные в базу данных (пароль хешируется для безопасности)
4. **Backend** отправляет код подтверждения на email
5. **Backend** отвечает Frontend: "OK, код отправлен"

## Технологии и инструменты

### Python 3.11+

**Python** - это язык программирования, на котором написан наш Backend. Это как язык, на котором говорит сервер.

**Почему Python?**
- Простой и понятный синтаксис
- Много готовых библиотек (как готовые инструменты)
- Хорошо работает с базами данных
- Поддерживает асинхронность (может обрабатывать много запросов одновременно)

### FastAPI

**FastAPI** - это фреймворк (набор инструментов) для создания API (Application Programming Interface - интерфейс для общения между программами).

**Что такое API?** Представьте меню в ресторане. API - это список блюд (функций), которые может заказать Frontend у Backend:
- "Дай список чатов" → Backend возвращает список
- "Отправь сообщение" → Backend сохраняет и отправляет сообщение
- "Найди собеседника" → Backend ищет подходящего пользователя

**Почему FastAPI?**
- Очень быстрый (быстрее многих других фреймворков)
- Автоматически создает документацию API
- Поддерживает асинхронность
- Встроенная валидация данных

**Пример простого API endpoint:**
```python
@router.get("/users/{user_id}")
async def get_user(user_id: int):
    """Получить информацию о пользователе"""
    return {"id": user_id, "name": "Иван"}
```

Когда Frontend делает запрос `GET /users/123`, Backend возвращает `{"id": 123, "name": "Иван"}`.

### SQLAlchemy

**SQLAlchemy** - это инструмент для работы с базами данных. Это как переводчик между Python и базой данных.

**Что такое база данных?** Представьте огромную таблицу Excel, где хранятся все данные:
- Таблица "users" - все пользователи
- Таблица "messages" - все сообщения
- Таблица "chats" - все чаты

**SQLAlchemy** позволяет:
- Создавать таблицы (модели данных)
- Добавлять, изменять, удалять данные
- Искать данные по условиям

**Пример модели:**
```python
class User(Base):
    id: int
    email: str
    nickname: str
    password_hash: str
```

Это описание таблицы "users" с колонками id, email, nickname, password_hash.

### PostgreSQL

**PostgreSQL** - это сама база данных (программа, которая хранит данные). Это как Excel, но для серверов.

**Почему PostgreSQL?**
- Надежная (данные не потеряются)
- Быстрая (быстро находит нужные данные)
- Поддерживает сложные запросы
- Бесплатная и открытая

**Как это работает:**
1. Backend говорит SQLAlchemy: "Сохрани пользователя"
2. SQLAlchemy переводит это в SQL (язык баз данных): `INSERT INTO users ...`
3. PostgreSQL выполняет команду и сохраняет данные

### Alembic

**Alembic** - это инструмент для миграций базы данных. Миграция - это изменение структуры базы данных.

**Зачем нужны миграции?** Представьте, что вы хотите добавить новую колонку "bio" в таблицу users. Миграция - это скрипт, который:
1. Добавляет колонку "bio" в таблицу users
2. Заполняет её значениями для существующих пользователей
3. Сохраняет историю изменений

**Пример миграции:**
```python
def upgrade():
    op.add_column('users', sa.Column('bio', sa.Text(), nullable=True))
```

Это добавляет колонку "bio" в таблицу "users".

### Pydantic

**Pydantic** - это библиотека для валидации данных. Она проверяет, что данные правильные перед их использованием.

**Пример:**
```python
class UserCreate(BaseModel):
    email: EmailStr  # Должен быть правильным email
    password: str = Field(min_length=8)  # Минимум 8 символов
```

Если Frontend отправит email `"неправильный-email"`, Pydantic вернет ошибку: "Неправильный формат email".

### WebSocket

**WebSocket** - это протокол для двусторонней связи в реальном времени. Обычный HTTP работает так:
1. Frontend спрашивает: "Есть новые сообщения?"
2. Backend отвечает: "Нет"
3. Через 2 секунды Frontend снова спрашивает: "Есть новые сообщения?"
4. Backend отвечает: "Да, вот сообщение"

**WebSocket** работает так:
1. Frontend открывает соединение
2. Backend может сам отправлять данные в любой момент: "Вот новое сообщение!"
3. Frontend может отправлять данные: "Отправь это сообщение"

**Аналогия:** HTTP - это телефон, где нужно звонить каждый раз. WebSocket - это рация, где можно говорить в любой момент.

**Пример WebSocket в нашем проекте:**
```python
@router.websocket("/chat/{chat_id}/ws/{email}")
async def chat_websocket(websocket: WebSocket, chat_id: int, email: str):
    await websocket.accept()  # Принимаем соединение
    
    while True:
        data = await websocket.receive_text()  # Получаем сообщение
        # Отправляем всем участникам чата
        await websocket.send_text(f"Новое сообщение: {data}")
```

### JWT (JSON Web Tokens)

**JWT** - это способ аутентификации (проверки, что пользователь действительно тот, за кого себя выдает).

**Как это работает:**
1. Пользователь вводит email и пароль
2. Backend проверяет пароль
3. Если пароль правильный, Backend создает токен (как пропуск)
4. Frontend сохраняет токен
5. При каждом запросе Frontend отправляет токен
6. Backend проверяет токен и разрешает доступ

**Токен выглядит так:**
```
eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJ1c2VyX2lkIjoxMjN9.signature
```

Это зашифрованная информация о пользователе.

### bcrypt

**bcrypt** - это алгоритм хеширования паролей. Хеширование - это преобразование пароля в нечитаемую строку.

**Зачем?** Если кто-то украдет базу данных, он не увидит реальные пароли, только хеши.

**Пример:**
- Пароль: `"mypassword123"`
- Хеш: `"$2b$12$LQv3c1yqBWVHxkd0LHAkCOYz6TtxMQJqhN8/LewY5GyYq5q5q5q5q"`

Даже если злоумышленник увидит хеш, он не сможет восстановить пароль.

### Описание основных файлов

#### `main.py` - Точка входа

Это главный файл, который запускает приложение. Он:
- Создает FastAPI приложение
- Подключает все роутеры (API endpoints)
- Настраивает CORS (разрешает запросы с Frontend)
- Настраивает обработку ошибок
- Запускает сервер

**Пример:**
```python
app = FastAPI(title="SoftSpeak API")
app.include_router(auth_router)  # Подключаем роутер аутентификации
app.include_router(chat_router)  # Подключаем роутер чата
```

#### `api/` - API Endpoints

Каждый файл в этой папке содержит роутеры (маршруты) для определенной функциональности.

**Пример из `auth.py`:**
```python
router = APIRouter(prefix="/auth", tags=["auth"])

@router.post("/login")
async def login(request_data: LoginRequest):
    # Проверяем email и пароль
    user = await authenticate_user(request_data.email, request_data.password)
    return {"token": "..."}
```

Это создает endpoint `POST /auth/login`.

#### `db/models.py` - Модели данных

Здесь описываются таблицы базы данных.

**Пример:**
```python
class User(Base):
    __tablename__ = "users"
    
    id: int
    email: str
    nickname: str
    password_hash: str
```

Это создает таблицу "users" с колонками id, email, nickname, password_hash.

#### `db/crud/` - CRUD операции

CRUD = Create (создать), Read (прочитать), Update (обновить), Delete (удалить).

Здесь функции для работы с данными:
- `get_user_by_email()` - найти пользователя по email
- `create_user()` - создать пользователя
- `update_user()` - обновить пользователя
- `delete_user()` - удалить пользователя

#### `schemas/` - Валидация данных

Здесь Pydantic схемы для проверки данных.

**Пример:**
```python
class LoginRequest(BaseModel):
    email: EmailStr  # Должен быть правильным email
    password: SecretStr  # Секретная строка (пароль)
```

Если Frontend отправит неправильные данные, Pydantic вернет ошибку.

## Установка и запуск

### Требования

- **Python 3.11+** - язык программирования
- **PostgreSQL 16** - база данных
- **Docker** (опционально) - для контейнеризации

### Установка через Docker (рекомендуется)

**Docker** - это инструмент, который упаковывает приложение и все его зависимости в "контейнер". Это как коробка, в которой есть все необходимое для работы приложения.

**Преимущества Docker:**
- Не нужно устанавливать Python, PostgreSQL и другие программы вручную
- Работает одинаково на любой системе
- Легко развернуть на сервере

**Шаги:**

1. **Убедитесь, что Docker установлен:**
```bash
docker --version
docker-compose --version
```

2. **Создайте файл `.env` в корне проекта:**
```env
DATABASE_URL=postgresql+asyncpg://user:password@db:5432/softspeak_db
JWT_SECRET=ваш-секретный-ключ-минимум-32-символа
DEV_MODE=true
```

3. **Запустите через Docker Compose:**
```bash
docker-compose up -d backend
```

Это создаст контейнер и запустит Backend.

### Установка вручную (для разработки)

1. **Установите Python 3.11+**

2. **Установите uv (менеджер пакетов):**
```bash
pip install uv
```

3. **Установите зависимости:**
```bash
cd backend
uv sync
```

4. **Настройте базу данных:**
```bash
# Создайте базу данных PostgreSQL
createdb softspeak_db

# Запустите миграции
cd src
uv run alembic upgrade head
```

5. **Запустите сервер:**
```bash
uv run uvicorn src.main:app --host 0.0.0.0 --port 8000 --reload
```

Флаг `--reload` означает, что сервер автоматически перезапустится при изменении кода (удобно для разработки).

### Проверка работы

Откройте в браузере:
- `http://localhost:8000/docs` - автоматическая документация API (Swagger UI)
- `http://localhost:8000/health` - проверка здоровья сервиса (должен вернуть `{"status": "ok"}`)

## База данных

### Что такое база данных?

**База данных** - это организованное хранилище данных. Представьте библиотеку:
- **Книги** (данные) хранятся на **полках** (таблицы)
- У каждой книги есть **название, автор, год** (колонки)
- **Библиотекарь** (PostgreSQL) знает, где какая книга

### Основные таблицы

#### `users` - Пользователи

Хранит информацию о пользователях:
- `id` - уникальный номер
- `email` - email адрес (уникальный)
- `nickname` - никнейм (уникальный)
- `password_hash` - хеш пароля (не сам пароль!)
- `is_active` - активен ли пользователь
- `is_banned` - забанен ли пользователь
- `bio` - описание пользователя
- `notification_anon_chats` - уведомления о новых анонимных чатах
- `notification_open_chats` - уведомления о новых открытых чатах

#### `email_verification_codes` - Коды подтверждения

Хранит коды для подтверждения email:
- `id` - уникальный номер
- `user_id` - ID пользователя
- `code` - код подтверждения (например, "123456")
- `created_at` - когда создан
- `expires_at` - когда истекает
- `is_used` - использован ли код

#### `chats` - AI чаты

Хранит чаты с AI ботом:
- `id` - уникальный номер
- `user_id` - ID пользователя
- `is_active` - активен ли чат

#### `messages` - Сообщения в AI чатах

Хранит сообщения в AI чатах:
- `id` - уникальный номер
- `chat_id` - ID чата
- `text` - текст сообщения
- `is_from_user` - от пользователя или от бота
- `created_at` - когда отправлено

#### `anonymous_chats` - Анонимные чаты

Хранит анонимные чаты между пользователями:
- `id` - уникальный номер
- `user1_id` - ID первого пользователя
- `user2_id` - ID второго пользователя
- `is_public` - раскрыт ли чат (показываются ли реальные никнеймы)
- `is_blocked` - заблокирован ли чат
- `user1_alias` - псевдоним первого пользователя (например, "Синий Кот")
- `user2_alias` - псевдоним второго пользователя
- `created_at` - когда создан

#### `anonymous_messages` - Сообщения в анонимных чатах

Хранит сообщения в анонимных чатах:
- `id` - уникальный номер
- `chat_id` - ID чата
- `sender_id` - ID отправителя
- `content` - текст сообщения
- `created_at` - когда отправлено
- `read_at` - когда прочитано

#### `matchmaking_queue` - Очередь матчмейкинга

Хранит пользователей, которые ищут собеседника:
- `id` - уникальный номер
- `user_id` - ID пользователя
- `created_at` - когда добавлен в очередь
- `status` - статус (waiting, matched)

#### `psychological_profiles` - Психологические профили

Хранит психологические профили пользователей:
- `id` - уникальный номер
- `user_id` - ID пользователя
- `vector` - вектор профиля (массив чисел для поиска совпадений)
- `created_at` - когда создан
- `updated_at` - когда обновлен

#### `user_answers` - Ответы на вопросы опроса

Хранит ответы пользователей на вопросы психологического опроса:
- `id` - уникальный номер
- `user_id` - ID пользователя
- `question_id` - ID вопроса
- `answer_text` - текст ответа
- `created_at` - когда ответил

#### `questions` - Вопросы опроса

Хранит вопросы психологического опроса:
- `id` - уникальный номер
- `category_id` - ID категории
- `text` - текст вопроса
- `order_index` - порядок вопроса
- `is_active` - активен ли вопрос

#### `categories` - Категории вопросов

Хранит категории вопросов:
- `id` - уникальный номер
- `name` - название категории
- `description` - описание категории

#### `reports` - Жалобы

Хранит жалобы пользователей:
- `id` - уникальный номер
- `reporter_id` - ID того, кто пожаловался
- `reported_user_id` - ID того, на кого пожаловались
- `chat_id` - ID чата
- `reason` - причина жалобы
- `description` - описание
- `status` - статус (pending, resolved, rejected)
- `created_at` - когда создана

#### `notifications` - Уведомления

Хранит уведомления пользователей:
- `id` - уникальный номер
- `user_id` - ID пользователя
- `type` - тип уведомления (new_chat, new_message, etc.)
- `message` - текст уведомления
- `is_read` - прочитано ли
- `created_at` - когда создано

### Миграции базы данных

**Миграция** - это изменение структуры базы данных. Например, добавление новой колонки или таблицы.

**Как создать миграцию:**
```bash
cd backend/src
uv run alembic revision --autogenerate -m "описание изменений"
```

Это создаст файл в `app/migrations/versions/` с описанием изменений.

**Как применить миграцию:**
```bash
uv run alembic upgrade head
```

Это применит все непримененные миграции.

**Как откатить миграцию:**
```bash
uv run alembic downgrade -1
```

Это откатит последнюю миграцию.

**API Endpoint** - это адрес, по которому можно обратиться к Backend. Это как номер телефона для определенной функции.

## WebSocket соединения

### Что такое WebSocket?

**WebSocket** - это протокол для двусторонней связи в реальном времени. В отличие от обычного HTTP, где Frontend должен постоянно спрашивать "есть ли новые данные?", WebSocket позволяет Backend самому отправлять данные в любой момент.

**Аналогия:**
- **HTTP** - это телефон, где нужно звонить каждый раз, чтобы узнать новости
- **WebSocket** - это рация, где можно говорить в любой момент

### WebSocket для матчмейкинга

**Endpoint:** `/api/matchmaking/ws/{email}`

**Что делает:** Отправляет уведомления о найденных совпадениях в реальном времени.

**Как подключиться (JavaScript):**
```javascript
const ws = new WebSocket('ws://localhost:8000/api/matchmaking/ws/user@mail.ru');

ws.onmessage = (event) => {
  const data = JSON.parse(event.data);
  if (data.type === 'match_found') {
    console.log('Найден собеседник!', data.chat_id);
  }
};
```

**Типы сообщений:**
- `match_found` - найден собеседник
- `queue_update` - обновление очереди
- `error` - ошибка

### WebSocket для анонимных чатов

**Endpoint:** `/api/matchmaking/chat/{chat_id}/ws/{email}`

**Что делает:** Обеспечивает real-time коммуникацию в анонимном чате.

**Как это работает:**
1. Frontend открывает WebSocket соединение
2. Backend добавляет соединение в список активных соединений чата
3. Когда кто-то отправляет сообщение, Backend отправляет его всем участникам через WebSocket
4. Frontend получает сообщение и отображает его

**Пример отправки сообщения:**
```javascript
ws.send(JSON.stringify({
  type: 'message',
  text: 'Привет!'
}));
```

**Пример получения сообщения:**
```javascript
ws.onmessage = (event) => {
  const data = JSON.parse(event.data);
  if (data.type === 'new_message') {
    console.log('Новое сообщение:', data.message);
  }
};
```

### WebSocket для психологического опроса

**Endpoint:** `/ws/survey/{email}`

**Что делает:** Отправляет вопросы опроса в реальном времени.

**Как это работает:**
1. Frontend открывает WebSocket соединение
2. Backend отправляет первый вопрос
3. Frontend отправляет ответ
4. Backend отправляет следующий вопрос
5. И так далее, пока не закончатся вопросы

## Аутентификация и безопасность

### JWT токены

**JWT (JSON Web Token)** - это способ аутентификации без хранения сессий на сервере.

**Структура токена:**
```
header.payload.signature
```

- **header** - информация о типе токена
- **payload** - данные о пользователе (email, id)
- **signature** - подпись для проверки подлинности

**Как это работает:**
1. Пользователь вводит email и пароль
2. Backend проверяет пароль
3. Backend создает JWT токен с данными пользователя
4. Frontend сохраняет токен
5. При каждом запросе Frontend отправляет токен в заголовке `Authorization: Bearer <token>`
6. Backend проверяет токен и разрешает доступ

**Пример создания токена:**
```python
import jwt
from datetime import datetime, timedelta

def create_access_token(email: str):
    expire = datetime.utcnow() + timedelta(minutes=30)
    payload = {
        "sub": email,
        "exp": expire
    }
    token = jwt.encode(payload, SECRET_KEY, algorithm="HS256")
    return token
```

**Пример проверки токена:**
```python
def verify_token(token: str):
    try:
        payload = jwt.decode(token, SECRET_KEY, algorithms=["HS256"])
        return payload["sub"]  # email пользователя
    except jwt.ExpiredSignatureError:
        raise HTTPException(401, "Токен истек")
    except jwt.InvalidTokenError:
        raise HTTPException(401, "Неверный токен")
```

### Хеширование паролей

**Хеширование** - это преобразование пароля в нечитаемую строку. Даже если кто-то украдет базу данных, он не увидит реальные пароли.

**Используется bcrypt:**
```python
import bcrypt

# Хеширование пароля
password = "mypassword123"
salt = bcrypt.gensalt()
hashed = bcrypt.hashpw(password.encode(), salt)

# Проверка пароля
is_valid = bcrypt.checkpw(password.encode(), hashed)
```

**Почему bcrypt?**
- Медленный (защита от брутфорса)
- Использует "соль" (случайные данные для уникальности)
- Проверенный алгоритм

### Rate Limiting

**Rate Limiting** - это ограничение количества запросов от одного пользователя. Защита от спама и DDoS атак.

**Используется slowapi:**
```python
from slowapi import Limiter
from slowapi.util import get_remote_address

limiter = Limiter(key_func=get_remote_address)

@router.post("/email/request")
@limiter.limit("5/hour")  # Максимум 5 запросов в час
async def request_code(request: Request):
    ...
```

**Примеры ограничений:**
- Email коды: 5 запросов в час
- Логин: 10 попыток в минуту
- Сообщения: 100 сообщений в минуту

### Валидация данных

**Валидация** - это проверка, что данные правильные перед их использованием.

**Используется Pydantic:**
```python
from pydantic import BaseModel, EmailStr, Field

class UserCreate(BaseModel):
    email: EmailStr  # Должен быть правильным email
    password: str = Field(min_length=8)  # Минимум 8 символов
    nickname: str = Field(min_length=3, max_length=32)  # От 3 до 32 символов
```

Если Frontend отправит неправильные данные, Pydantic вернет ошибку:
```json
{
  "detail": [
    {
      "loc": ["body", "email"],
      "msg": "value is not a valid email address",
      "type": "value_error.email"
    }
  ]
}
```

### Проверка прав доступа

**Проверка прав** - это проверка, что пользователь имеет право выполнить действие.

**Примеры:**
- Только участник чата может отправлять сообщения
- Только владелец профиля может его изменять
- Только админ может банить пользователей

**Пример:**
```python
async def verify_user_in_chat(chat_id: int, user_id: int, session: AsyncSession):
    chat = await get_chat(session, chat_id)
    if chat.user1_id != user_id and chat.user2_id != user_id:
        raise HTTPException(403, "Вы не участник этого чата")
```

## Отправка email

### Что такое SMTP?

**SMTP (Simple Mail Transfer Protocol)** - это протокол для отправки email. Это как почтовая служба для интернета.

**Как это работает:**
1. Backend подключается к SMTP серверу (например, smtp.yandex.ru)
2. Backend авторизуется (вводит логин и пароль)
3. Backend отправляет письмо
4. SMTP сервер доставляет письмо получателю

### Поддерживаемые провайдеры

#### Yandex
- **SMTP сервер:** `smtp.yandex.ru`
- **Порт:** 465 (SSL)
- **Требуется:** Пароль приложения (не основной пароль!)

**Как получить пароль приложения:**
1. Зайдите в настройки Yandex
2. Перейдите в "Безопасность"
3. Создайте пароль приложения
4. Используйте этот пароль в настройках

#### Mail.ru
- **SMTP сервер:** `smtp.mail.ru`
- **Порт:** 465 (SSL)
- **Требуется:** Пароль приложения

#### Gmail
- **SMTP сервер:** `smtp.gmail.com`
- **Порт:** 587 (STARTTLS)
- **Требуется:** Пароль приложения

### Настройка в .env

```env
DEV_MODE=false  # true = MailHog (для разработки), false = реальный SMTP
EMAIL_FROM=noreply@yandex.ru
SMTP_HOST=smtp.yandex.ru
SMTP_PORT=465
SMTP_USER=noreply@yandex.ru
SMTP_PASSWORD=пароль_приложения
SMTP_USE_TLS=false  # false для SSL (465), true для STARTTLS (587)
```

### Как это работает в коде

**Файл:** `core/email.py`

```python
async def send_email_async(subject: str, body: str, recipient: str):
    # Создаем сообщение
    message = EmailMessage()
    message["Subject"] = subject
    message["From"] = settings.email_from
    message["To"] = recipient
    message.set_content(body)
    
    # Определяем SMTP настройки по домену email
    domain = settings.email_from.split("@")[-1]
    if "yandex" in domain:
        smtp_host = "smtp.yandex.ru"
        smtp_port = 465
        use_ssl = True
    elif "mail.ru" in domain:
        smtp_host = "smtp.mail.ru"
        smtp_port = 465
        use_ssl = True
    elif "gmail.com" in domain:
        smtp_host = "smtp.gmail.com"
        smtp_port = 587
        use_ssl = False  # STARTTLS
    
    # Отправляем
    if use_ssl:
        with smtplib.SMTP_SSL(smtp_host, smtp_port) as server:
            server.login(settings.smtp_user, settings.smtp_password)
            server.send_message(message)
    else:
        with smtplib.SMTP(smtp_host, smtp_port) as server:
            server.starttls()
            server.login(settings.smtp_user, settings.smtp_password)
            server.send_message(message)
```

## Матчмейкинг

### Что такое матчмейкинг?

**Матчмейкинг** - это поиск подходящих собеседников на основе психологического профиля.

### Как это работает?

1. **Пользователь проходит опрос:**
   - Отвечает на вопросы о себе
   - Каждый ответ преобразуется в вектор (эмбеддинг)
   - Все векторы объединяются в один профильный вектор

2. **Пользователь начинает поиск:**
   - Backend добавляет пользователя в очередь
   - Backend получает вектор профиля пользователя

3. **Backend ищет совпадения:**
   - Сравнивает вектор пользователя с векторами других пользователей в очереди
   - Использует косинусное расстояние (мера схожести)
   - Находит пользователя с наименьшим расстоянием (наибольшей схожестью)

4. **Backend создает чат:**
   - Если схожесть выше порога (0.65), создается анонимный чат
   - Пользователям присваиваются случайные имена (например, "Синий Кот")
   - Отправляется уведомление через WebSocket

### Психологический профиль

**Психологический профиль** - это вектор (массив чисел), который описывает личность пользователя на основе его ответов.

**Как создается:**
1. Пользователь отвечает на вопросы
2. Каждый ответ преобразуется в эмбеддинг (вектор) через ML модель
3. Все эмбеддинги объединяются в один профильный вектор
4. Вектор нормализуется (приводится к единичной длине)

**Пример:**
```python
# Ответы пользователя
answers = [
    "Я люблю читать книги",
    "Мне нравится спорт",
    "Я предпочитаю одиночество"
]

# Каждый ответ → эмбеддинг (768 чисел)
embeddings = [
    [0.1, 0.2, 0.3, ...],  # эмбеддинг первого ответа
    [0.2, 0.3, 0.4, ...],  # эмбеддинг второго ответа
    [0.3, 0.4, 0.5, ...]   # эмбеддинг третьего ответа
]

# Объединение в профильный вектор
profile_vector = average(embeddings)  # [0.2, 0.3, 0.4, ...]
```

### Поиск совпадений

**Косинусное расстояние** - это мера схожести между двумя векторами.

**Формула:**
```
similarity = dot_product(vector1, vector2) / (length(vector1) * length(vector2))
```

**Пример:**
- Вектор пользователя A: `[0.5, 0.5, 0.5]`
- Вектор пользователя B: `[0.6, 0.4, 0.5]`
- Схожесть: `0.98` (очень похожи!)

**Порог схожести:** 0.65 (настраивается в конфиге)

Если схожесть >= 0.65, пользователи считаются подходящими.

### Случайные имена

**Случайные имена** - это псевдонимы для анонимных чатов (например, "Синий Кот", "Веселый Пес").

**Как создаются:**
- Прилагательное + Существительное
- Берется из базы данных `random_adjectives` и `random_nouns`
- Уникальные для каждого чата

**Пример:**
- Прилагательные: ["Синий", "Красный", "Веселый"]
- Существительные: ["Кот", "Пес", "Слон"]
- Результат: "Синий Кот", "Красный Пес"

## Логирование и отладка

### Логирование

**Логирование** - это запись событий в файл или консоль для отладки.

**Уровни логов:**
- `DEBUG` - детальная информация (для разработки)
- `INFO` - общая информация (обычные события)
- `WARNING` - предупреждения (что-то не так, но работает)
- `ERROR` - ошибки (что-то сломалось)
- `CRITICAL` - критические ошибки (приложение не может работать)

**Пример:**
```python
import logging

logger = logging.getLogger(__name__)

logger.info("Пользователь зарегистрирован")
logger.warning("Неверный формат email")
logger.error("Ошибка подключения к БД")
```

### Просмотр логов

**В Docker:**
```bash
docker-compose logs -f backend
```

**В консоли:**
Логи выводятся в консоль при запуске через `uvicorn`.

### Отладка

**Отладка** - это процесс поиска и исправления ошибок.

**Инструменты:**
- **Логи** - смотрите логи для понимания, что происходит
- **Swagger UI** - `http://localhost:8000/docs` для тестирования API
- **Postman** - инструмент для тестирования API
- **Python debugger** - встроенный отладчик Python

**Пример использования debugger:**
```python
import pdb

def some_function():
    pdb.set_trace()  # Остановка здесь для отладки
    # Код после этой строки выполняется пошагово
```

## Типичные проблемы и решения

### Проблема: "Database connection error"

**Причина:** Неправильные настройки подключения к БД.

**Решение:**
1. Проверьте `DATABASE_URL` в `.env`
2. Убедитесь, что PostgreSQL запущен
3. Проверьте, что база данных существует

### Проблема: "JWT secret is too short"

**Причина:** `JWT_SECRET` меньше 32 символов.

**Решение:**
Создайте длинный случайный ключ:
```bash
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

### Проблема: "Email not sent"

**Причина:** Неправильные настройки SMTP.

**Решение:**
1. Проверьте `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`
2. Убедитесь, что используете пароль приложения (не основной пароль)
3. Проверьте, что `DEV_MODE=false` для продакшена

### Проблема: "Migration error"

**Причина:** Конфликт миграций.

**Решение:**
```bash
# Откатите миграции
uv run alembic downgrade -1

# Примените заново
uv run alembic upgrade head
```

### Проблема: "WebSocket connection failed"

**Причина:** Проблемы с проксированием или CORS.

**Решение:**
1. Проверьте настройки Nginx для WebSocket
2. Проверьте CORS настройки
3. Убедитесь, что WebSocket endpoint правильный
